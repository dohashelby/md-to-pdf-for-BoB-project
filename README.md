# make_report_html.py — Markdown 보고서를 표지가 붙은 HTML·PDF로

번뜩번뜩 작은별 보고서를 Markdown으로 쓰면, 표지·목차·도표 형식이 갖춰진 HTML(선택: PDF)로 바꿔 주는 스크립트다.
디자인은 맥킨지 코리아 리포트 형식(들여 쓴 본문 단, "도표 N" 형식의 표·그래프)을 참고했고,
색은 다섯 가지(#0B163F, #6688CC, #FFD45C, #F7F8FC, #E5E7EB), 글꼴은 Pretendard를 쓴다.

## 1. 준비물

| 항목 | 필요 여부 | 비고 |
| --- | --- | --- |
| Python 3.9 이상 | 필수 | 표준 라이브러리만 쓴다. 따로 설치할 패키지 없음 |
| `표지.png` | 필수 | 스크립트와 같은 폴더에 둔다. A4 비율(210:297) 이미지 |
| Google Chrome | PDF를 만들 때 | `--pdf` 옵션이 Chrome을 headless로 실행한다 |
| 인터넷 | 권장 | Pretendard 웹폰트(jsDelivr)를 받는다. Pretendard가 설치돼 있으면 없어도 된다 |
| `sips` (macOS 기본) | 선택 | 있으면 표지 PNG를 JPEG로 줄여 넣는다 |

## 2. 실행

```bash
python3 make_report_html.py 1.md -o 출력/보고서.pdf
```

| 옵션 | 뜻 | 기본값 |
| --- | --- | --- |
| `-o, --output` | 출력 경로. 확장자가 `.pdf`면 PDF를 만든다 | 입력 파일과 같은 이름의 `.html` |
| `--pdf` | HTML 대신 PDF만 만든다(`-o`의 확장자는 `.pdf`로 바뀐다) | 끔 |
| `--cover 파일` | 표지 배경 이미지(.png·.jpg) 또는 .docx | 스크립트 옆 `표지.png` |
| `--toc-depth 2·3·0` | 목차 깊이. 2는 장만, 3은 절까지, 0은 목차 없음 | 2 |
| `--no-chapter-break` | 인쇄할 때 `##` 장마다 새 쪽으로 넘기지 않는다 | 장마다 새 쪽 |
| `--title`, `--team`, `--date`, `--cover-title`, `--cover-label` | 표지 문구. front matter보다 우선한다 | — |

출력 결과:

- **최종 파일 하나만 생긴다.** HTML이면 `보고서.html`, PDF면 `보고서.pdf`만 생긴다. 자료 폴더(`_assets`)는 만들지 않는다.
- HTML에는 표지 이미지가 들어 있어 파일 하나만 옮기면 된다.
- PDF를 만들 때 쓰는 중간 HTML은 임시 폴더에서 만들고 바로 지운다.
- Chrome을 찾지 못하면 PDF 대신 같은 이름의 HTML을 만들고 그 사실을 알려 준다.

HTML을 Chrome에서 열고 직접 인쇄(⌘P → PDF로 저장)해도 같은 결과가 나온다. 배경색이 인쇄되도록 설정해 두었으므로 "배경 그래픽" 옵션은 켜지 않아도 된다.

## 3. 표지

표지는 `표지.png`를 A4 전면 배경으로 깔고, 그 위에 글자를 올린다.

| 표지 요소 | 들어가는 내용 | 정하는 방법 |
| --- | --- | --- |
| 로고 아래 팀 이름 | "번뜩번뜩작은별" | front matter `team` 또는 `--team` |
| 큰 제목 | 보고서 제목. 배경 경계에서 글자색이 네이비 ↔ 밝은색으로 바뀐다 | `title` (줄바꿈은 `cover_title`) |
| 큰 제목 위 작은 문구 | 기본은 없음 | `cover_label` |
| 아래쪽 날짜 | 작성 기준일의 날짜만 | `date`, 없으면 본문 첫 줄의 "작성 기준일 YYYY-MM-DD" |

### 3.1 front matter (선택)

Markdown 맨 앞에 넣는다. 없어도 된다.

```markdown
---
title: LLM 서빙 엔진 업데이트 보안 검증 조사보고서
cover_title: LLM 서빙 엔진 | 업데이트 보안 검증 | 조사보고서
team: 번뜩번뜩작은별
date: 2026-10-03
cover_label: 프로젝트 사전조사 보고서
---
```

- `cover_title`은 `|`로 큰 제목의 줄을 직접 나눈다. 없으면 제목 길이에 맞춰 자동으로 나누고 글자 크기를 정한다.
- `subtitle`, `version`도 읽기는 하지만 지금 표지에는 표시하지 않는다.

### 3.2 front matter가 없을 때

- 첫 번째 `# 제목`이 표지 제목이 되고, 본문에서는 빠진다.
- 제목 바로 아래 줄이 `·`로 이어진 한 줄 문단이면 본문에서 빼고, 그 안의 "작성 기준일 YYYY-MM-DD"에서 날짜를 가져온다.

```markdown
# LLM 서빙 엔진 업데이트 보안 검증 조사보고서

1차 발표용 조사보고서 · 번뜩번뜩 작은별 · 작성 기준일 2026-10-03 · **검토용 초안 v0.3**
```

### 3.3 표지 이미지를 바꿀 때

스크립트 CSS 맨 위의 세 값을 새 이미지에 맞춰 고친다. 모두 이미지 폭에 대한 백분율이다.

| 변수 | 뜻 | 현재 값 |
| --- | --- | --- |
| `--split` | 크림색과 네이비 배경의 경계. 큰 제목의 색이 바뀌는 위치 | 36.209% |
| `--logo-left` | BBLS 로고의 왼쪽 끝. 제목·팀 이름·날짜가 여기에 맞춰진다 | 3.79% |
| `--logo-width` | 로고 폭. 팀 이름과 날짜를 이 폭 안에서 가운데 정렬한다 | 28.53% |

## 4. Markdown 작성 요령

### 4.1 제목과 쪽 나눔

| 쓰는 법 | 결과 |
| --- | --- |
| `# 제목` (첫 번째) | 표지 제목이 되고 본문에서는 빠진다 |
| `## 1. 서빙 엔진 시장` | 작은 "Chapter 1" 라벨 + 큰 장 제목. 인쇄 시 새 쪽에서 시작한다 |
| `## 부록 A. 설문지` | 작은 "부록 A" 라벨 + 큰 장 제목 |
| `## 참고문헌` (번호 없음) | 라벨 없이 큰 장 제목 |
| `### 1.1 소제목` | 굵은 소제목(목차는 `--toc-depth 3`일 때만 표시) |
| `####` | 작은 굵은 제목 |
| `---` | 가는 구분선. 단, `##` 바로 앞의 `---`는 쪽 나눔과 겹쳐 빈 쪽을 만들기 때문에 자동으로 지운다 |

- 목차는 `##` 장으로 자동 생성된다. 쪽 번호는 넣지 않는다(Chrome PDF 변환의 한계).
- 쪽 아래에는 왼쪽에 보고서 제목, 오른쪽에 쪽 번호가 들어간다(표지 제외).

### 4.2 문단과 글자 꾸밈

| 쓰는 법 | 결과 |
| --- | --- |
| 빈 줄로 구분 | 문단. 한 문단 안의 줄바꿈은 공백으로 이어진다 |
| `**굵게**`, `*기울임*`, `` `코드` `` | 굵게, 기울임, 코드 글꼴 |
| `[글자](https://...)` | 링크 |
| `https://...` | 자동 링크 |
| `<br>` | 강제 줄바꿈(표 칸 안에서도 쓸 수 있다) |

### 4.3 목록

```markdown
- 항목
  - 들여 쓴 하위 항목 (2칸 이상 들여쓰기)
1. 번호 목록
3. 시작 번호는 첫 항목 번호를 따른다
```

### 4.4 참고문헌과 인용

참고문헌 목록에 `- [R01] …`처럼 대괄호 번호로 시작하는 항목을 두면, 본문의 인용이 그 항목으로 연결된다.

```markdown
본문 문장이다. [R01][R08~R11][T12]
권고 수는 다음과 같다. [R67, GitHub 권고 API 집계]

## 참고문헌
- [R01] LinkedIn — How we leveraged vLLM ...
- [T12] 팀 실험 자료 ...
```

- 연결되는 형식: `[R01]`, `[R08~R11]`(첫 번호로 연결), `[T12]`, `[R67, 설명]`(번호만 연결)
- 목록에 없는 번호는 연결하지 않고 그대로 둔다.
- 번호는 `R` 또는 `T` + 숫자 1~2자리다.

### 4.5 표와 도표 제목·출처

```markdown
도표: 대표 권고별로 다른 해당 여부 판단 조건

| 권고 | 영향 조건 | 수정 버전 |
| --- | :---: | ---: |
| CVE-2026-22807 | `trust_remote_code=False` 미적용 | 0.14.0 |

자료: GitHub 권고 API, 2026-10-04 대조.
```

- **도표 제목:** 표 바로 위 한 줄에 `도표: 제목`(또는 `Table: 제목`)을 쓰면 "도표 N" 라벨과 굵은 제목이 붙는다. 제목은 표가 말하는 결론을 담되 명사형으로 끝맺는다(예: "대표 권고별로 다른 해당 여부 판단 조건").
- **출처·주석:** 표 바로 다음 문단이 `출처`·`자료`·`주`·`Note`·`참고`로 시작하고 그 뒤에 `:`·`)`·`는 `이 오면 작은 회색 주석이 된다.
- **번호:** 제목이 있는 표와 다이어그램은 "도표 N" 번호를 함께 매긴다. 제목이 없는 표는 번호 없이 표만 나온다.
- **정렬:** 둘째 줄의 `:---:`는 가운데, `---:`는 오른쪽 정렬이다.
- **칸 안의 `|`:** `\|`로 쓴다.
- **모양:** 표는 쪽 폭을 다 쓰며, 첫 열은 자동으로 굵게 표시된다.

### 4.6 주석 상자 (해석 범위, 주의 등)

```markdown
> **해석 범위**
>
> - 공공기관의 실제 자체 서빙 규모를 보여 주는 통계는 없다.
> - 모델 카드의 하드웨어 요구는 해당 모델의 안내 조건이다.
```

- 첫 줄이 **굵은 글씨뿐**이면 그 글씨가 왼쪽 여백의 라벨이 되고, 내용은 위아래 가는 선 사이에 작은 글씨로 들어간다.
- 라벨 없이 `>`만 쓰면 같은 모양에서 라벨만 빠진다.
- 상자는 쪽 사이에서 잘리지 않는다. 그래서 긴 상자는 다음 쪽으로 넘어가며 앞 쪽 아래에 빈 공간이 생길 수 있다.

### 4.7 막대그래프 ` ```chart `

````markdown
```chart
type: bar
title: 하반기 석 달여 만에 상반기 전체를 넘어선 권고 공개 건수
subtitle: vLLM 보안 권고 수
unit: 건, GHSA ID 기준
source: GitHub Security Advisories(R67), 2026-10-04 집계
note: 하반기 증가 원인은 분석하지 않았다.
구분,검출,미검출
판단 로직형,4,0
호출형,4,14
```
````

| 머리 줄 | 뜻 |
| --- | --- |
| `type` | `bar` 세로 막대(기본), `hbar` 가로 막대 |
| `title` | 도표 제목(굵은 한 문장) |
| `subtitle`, `unit` | 그래프 위의 굵은 이름과 단위 |
| `source`, `note` | 그래프 아래 회색 주석. `source`는 앞에 "자료:"가 붙는다 |

- 머리 줄 다음은 CSV다. 첫 줄은 머리글(첫 칸은 항목 이름, 둘째 칸부터 계열 이름), 그다음 줄부터 데이터다.
- 계열 색은 네이비 → 블루 → 노랑 → 회청 순서다. 계열이 둘 이상이면 오른쪽 위에 범례가 생긴다.
- 값에 단위를 붙여도 된다(`23건`, `17.2%`). 막대 길이는 숫자만으로 계산하고, 라벨은 적은 그대로 표시한다.
- 항목 이름이나 값에 쉼표를 쓰면 안 된다(CSV 구분자). 필요하면 `·`를 쓴다.

### 4.8 가로 흐름 ` ```flow `

````markdown
```flow
title: 업무 앱과 게이트웨이를 거쳐 vLLM Pod에 이르는 요청 처리 경로
업무 앱 | 사용자·문서 권한 판단
게이트웨이 | 인증·모델 권한·요청 제한
vLLM Pod* | 모델 적재·요청 배치·추론
GPU | 연산 실행
aside: vLLM Pod | 업데이트 대상: 이미지·모델·실행 옵션
source: vLLM Kubernetes 배포 문서(R04)
```
````

- 한 줄이 상자 하나다. 형식은 `이름 | 설명`이고, 설명은 생략할 수 있다.
- 이름 끝에 `*`를 붙이면 네이비로 채운 강조 상자가 된다.
- 상자가 6개 이상이면 두 줄로 접고, 줄 사이를 꺾인 화살표로 잇는다(예: S1~S8 파이프라인).
- `aside: 이름 | 설명`을 쓰면 그 상자 아래에 점선 화살표와 보조 설명이 붙는다.
- 머리 줄 `title`, `subtitle`, `unit`, `source`, `note`는 chart와 같다.

### 4.9 2×2 매트릭스 ` ```matrix `

````markdown
```matrix
title: 기존 도구의 영역 분포와 비어 있는 엔진 정책 인지형 업데이트 전 검증 영역
x: 업데이트 전 검증 → 운영 중 감시
y: 범용(패키지·인프라·AI 시스템) → 엔진·기업 정책 인지
top-left*: 우리 (목표 위치) | 엔진 권고 × 배포 조건 → 시험 선정 → 버전 비교 → 증거
top-right: 확인 안 됨 | 공식 문서 범위에서 해당 도구를 확인하지 못함
bottom-left: 패키지·정책·시험 도구 | Trivy, Grype, Dependabot, OPA
bottom-right: 게이트웨이·런타임 도구 | Falco, Tetragon, LiteLLM, Kong
source: 공식 문서 기준 정리(5.2~5.4)
```
````

| 머리 줄 | 뜻 |
| --- | --- |
| `x: 왼쪽 → 오른쪽` | 열 이름. 위쪽에 가로 화살표와 함께 표시된다 |
| `y: 아래 → 위` | 행 이름. 순서가 **아래 → 위**임에 주의한다 |
| `top-left`, `top-right`, `bottom-left`, `bottom-right` | 각 칸의 내용. 형식은 `칸 제목 | 내용` |
| 칸 이름 뒤 `*` (예: `top-left*:`) | 네이비로 채운 강조 칸 + 노란 별 |

- **내용에 쉼표가 하나라도 있으면 쉼표마다 끊어 칩(둥근 이름표)으로 그린다.** 문장을 쓰는 칸에서는 쉼표 대신 `·`나 `→`를 쓴다.

### 4.10 번호 카드 ` ```steps `

````markdown
```steps
title: 기업의 6단계 엔진 업데이트 절차와 우리 프레임워크의 지원 범위(5단계)
legend: 우리 프레임워크가 지원하는 단계
columns: 3
*변경 검토 | 릴리스·권고·의존성·지원 모델 변경을 확인한다
단계적 배포 | 트래픽을 나눠 옮기고 되돌림을 준비한다
source: NIST SP 800-40r4(R16)
```
````

- 한 줄이 카드 하나다. 형식은 `제목 | 설명`이고, 카드 번호(1, 2, 3…)는 자동으로 붙는다.
- 줄 앞에 `*`를 붙이면 카드 오른쪽 위에 체크 표시가 생긴다. `legend`는 체크 표시의 설명이다.
- `columns`는 한 줄에 놓을 카드 수다(기본 3).

## 5. 자주 생기는 문제

| 증상 | 원인과 해결 |
| --- | --- |
| 목차 다음에 빈 쪽이 생긴다 | `##` 앞 `---`는 자동으로 지우므로, 다른 요소(빈 표 등)가 장 사이에 끼었는지 확인한다 |
| 표·주석 상자 앞쪽에 빈 공간이 크다 | 그 요소를 쪽 사이에서 자르지 않도록 해 두었기 때문이다. 내용을 줄이거나 `--no-chapter-break`로 장 나눔을 끈다 |
| 글꼴이 Pretendard가 아니다 | 인터넷 연결이 없고 Pretendard도 설치돼 있지 않은 경우다. Pretendard를 설치하거나 인터넷에 연결한다 |
| 다이어그램 글자가 상자 끝에 붙는다 | 글자 폭을 추정해 줄을 바꾸기 때문이다. 문구를 줄이거나 띄어쓰기를 넣어 줄바꿈 위치를 만든다 |
| 매트릭스 칸이 칩으로 쪼개진다 | 내용에 쉼표가 있어서다. 쉼표를 `·`로 바꾼다 |
| PDF가 만들어지지 않는다 | Chrome이 `/Applications/Google Chrome.app`에 있는지 확인한다 |
| 인용 `[R01]`이 링크가 안 된다 | 참고문헌 목록에 `- [R01] …` 항목이 있는지, 번호 형식(R/T + 숫자 1~2자리)이 맞는지 확인한다 |
